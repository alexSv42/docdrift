Product announcement

Your docs now fix themselves

docdrift is an autonomous agent that reads your API source code, finds every place your documentation has fallen out of step with it, and opens a pull request with the corrections already applied.

Vienna, Austria — Redocly announces general availability of docdrift, included with every Redocly workspace.

The problem

Nobody sets out to ship wrong documentation. It happens one small commit at a time. A query parameter is renamed from perPage to limit. A version prefix moves from /v1 to /v2. An X-Api-Key header is replaced by bearer tokens. A DELETE route is added and nobody thinks to mention it.

Each change takes seconds in the code and is invisible in the docs. Six months later your reference describes an API that no longer exists. Your support queue fills with integration problems that are really documentation problems. Your best-intentioned developers start reading the source instead of the docs — and once they stop trusting the docs, they never fully start again.

The work of fixing this is not hard. It is just endless, unrewarding, and always less urgent than the next feature. So it does not get done.

The solution

docdrift closes the loop. Point it at your code and your docs, and a team of specialised agents does the job a diligent technical writer would do, on every commit, in about a minute.

Scanner

Reads your controllers and DTOs and extracts the API as it truly is — every route, parameter, field, status code and auth scheme.

Auditor

Diffs that truth against your markdown and OpenAPI documents, and reports concrete, verifiable drift. Your own rules file joins its instructions.

Fixer

Rewrites the affected files, touching only what is wrong. Your prose, structure and voice survive intact.

Validator

Runs Redocly CLI over any specification the Fixer touched. If it does not lint, the errors go back to the Fixer until it does.

Reporter

Writes the pull request — findings grouped by severity, each change explained, and anything a human should double-check called out.

The code is always the source of truth. docdrift never edits your source, and it never opens a pull request it cannot explain.

How to use it

Install it, point it at two directories, and read the pull request.

# Check the docs against the code
npx docdrift --code ./src --docs ./docs

# See the proposed pull request without opening it
npx docdrift --code ./src --docs ./docs --dry-run
